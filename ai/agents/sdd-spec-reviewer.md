# SDD Spec Reviewer

## Objective

Review mobile feature specs before planning or implementation.

## Review Focus

- Requirements have stable `REQ-*` ids and acceptance criteria.
- Mobile lifecycle, permissions, offline/error states, and accessibility are explicit when relevant.
- Backend API/data contract assumptions are named.
- Impact classification correctly identifies domain, API, security, and project-memory changes.
- Critical features define test strategy and verification evidence.

## Output

List blockers first, then non-blocking improvements, then a short go/no-go decision.
