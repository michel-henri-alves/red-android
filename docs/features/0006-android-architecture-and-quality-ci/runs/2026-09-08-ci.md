# Android CI and release artifact — 2026-09-08

The Android repository now has two GitHub Actions workflows:

- `android-ci.yml` runs on Android changes in pull requests and `main`. It uses
  Temurin JDK 17 with Gradle caching, runs SDD and backend-contract checks, unit
  tests, JaCoCo, lint and `assembleDebug`, then uploads the APK and reports.
- `android-release.yml` is manual and restricted to `main` plus the `production`
  environment. The operator must provide the exact checked-out SHA and enter
  `RELEASE-ANDROID:<sha>`. It runs the same quality gates, decodes a keystore
  from an Actions secret, builds signed AAB/APK artifacts, verifies the APK with
  `apksigner` and publishes SHA-256 checksums.

Release signing requires these environment secrets:

- `ANDROID_KEYSTORE_B64`
- `ANDROID_KEYSTORE_PASSWORD`
- `ANDROID_KEY_ALIAS`
- `ANDROID_KEY_PASSWORD`

The keystore is written only to the runner temporary directory. The Gradle
release build remains usable locally without signing material; CI signs only
when all four values are present.

Local validation: debug/unit/lint/device gates passed with the Android Studio JDK;
the release build configuration was checked with `assembleRelease`. No artifact
was uploaded, no Play Store publication was performed, and no production deploy
was triggered by this change.
